# CLAUDE.md — Kandinski

A retro high-speed driving game on the Flint engine (Rad Racer / OutRun
lineage, "outrun" vector look). Three modes on one road technology: ARCADE
(the original five stages, a clock, checkpoints), the GRAND TOUR (15 events
in 5 legs, medals, unlocks) and HORIZON (an unending road, three crashes).

**North star:** speed you can read. Dark planes, thin neon lines, a sun on the
horizon; selective ASCII + bloom for the scenery so it reads as vintage vector
type. References in `reference/` (games, vibes, flint_fx) are mood, not a spec.

## Build, run, check

```
build.bat                         # cargo build --release in engine/
play.bat / play_windowed.bat      # scenes\kandinski.scene.toml
python tools/build_scene.py       # after changing pools or post-process
python tools/gen_tiles.py ; python tools/gen_models.py ; python tools/gen_hero.py ; python tools/gen_audio.py
                                  # gen_models.py also writes the first, low-poly car_player.glb: run gen_hero.py after it
python tools/gen_beat.py [--plot] # after the music changes: the pulse's table, and a check of the kicks against the score
tools/shot.sh auto_s2 12 snapshots/x.png     # frame at t=12 s of the self-driving stage-3 scene
tools/shot.sh kandinski 12 snapshots/x.png --input-script snapshots/flow.txt
python tools/telemetry.py             # every handling manoeuvre, measured and plotted (--rates: 30/60/144 fps)
python tools/telemetry.py stages      # the autopilot through each stage and the whole arcade run
python tools/tour_check.py            # all 15 events at autopilot skill 0.80 and 1.00, by the rules: table + pass/fail
python tools/tour_check.py --calibrate [n ...]   # re-measure and rewrite scripts/lib/tour_cal.rhai (then check)
python tools/capture.py x.png 9 autopilot=True start_event=8 start_stage=0 start_speed=70   # a frame inside an event's section
python tools/menu_flow.py first --save clean --inputs snapshots/tour/flow_first.txt --until 24.6 --every 0.5
python tools/touch_check.py [drive|flow] [phone|tablet]   # fingers, natively: numbers and frames in snapshots/touch/
engine/target/release/flint.exe export web . --out captures/web ; python -m http.server 8765 -d captures/web
node tools/web_touch.mjs "http://127.0.0.1:8765/?game=afterglow&perf=1" snapshots/web_touch phone   # fingers, in Chrome
```

Scene keywords for checks (`build_scene.build`, all game_state fields):
`start_event` (0-14, 100 = HORIZON; with `autopilot` and no `start_speed` the
event runs by its rules to the results screen and logs an `EVR` line),
`ap_skill`, `ap_style` (1 drifts, 2 shaves traffic, 3 burns boost),
`ap_assist` (menus stay the player's, the autopilot drives the events),
`no_clock`, `ghost_rivals` (race pace calibration), `persist` (off by default
in every test scene, so parallel runs and tests never touch the save).

**Do not edit scripts while a run is in flight**: the player hot-reloads a
changed script and the run restarts its state half way. A full tour_check
is about 100 minutes of game time: 25 minutes of wall clock at `--jobs 12`.

`auto_s<n>` scenes set `game_state.autopilot`: the game drives itself from the
first frame in stage n. Use them (with `--frame-step`) for every visual check;
`flint render` does not run the road script, so a plain render shows nothing
but parked pools. An input script can take any control back from the autopilot
in an `auto` scene while it holds it (steer, pedals, handbrake, boost).

## How the game is put together

- **Modes** (`game_state.mode`): `title` -> (`tour` -> `brief` ->) `countdown`
  -> `drive` -> `results` (events, HORIZON) or `over` / `finish` (arcade).
  drive.rhai owns the machine and every menu cursor except pause's; hud.rhai
  draws every screen from `game_state`. The attract loop runs under `title`
  and `tour` on whatever road is loaded.
- **An event is data**: a map in `scripts/lib/tour.rhai`'s `raw_events()`:
  `secs` (rows of `[theme, tiles, curve_max, hill_amp, curve_min, straight
  share]`, each a section that ends at a gate), `seed`, `traffic` (`[cars,
  slowest m/s, spread m/s, spawn spread m]`), `rivals` (skills) and `type`.
  The arcade run and HORIZON's first sections are maps of the same shape.
  **To add or change an event**: edit the map (three events a leg, ids
  `l<leg>e<n>`: the save is keyed by id), run `python tools/tour_check.py
  --calibrate <index>`, read its table. Race events have nothing to calibrate
  but their rival skills: the table prints every rival's time.
- **Loading a road** is one place in `on_update` (`req_load`, then
  `req_reset`): `gen_road` (pure) returns the track arrays, every tile is
  marked for recolouring, pools re-park themselves, traffic and the grid are
  placed. It runs behind the briefing card or the countdown's fade.
- **Types**: sprint (clock + gates, medal by seconds left), race (five
  rivals, medal by position), drift (the clock is the event, medal by points
  banked), rush (clock + traffic, medal by close passes, a crash limit),
  endurance (clock + gates, medal by score). `tour::medal_for` is the rule.
- **Calibration rules** are in tools/tour_check.py's docstring: clocks from
  the autopilot's skill-0.80 splits, gold from beating skill 1.00, DRIFT and
  RUSH targets from the autopilot's `ap_style` stand-ins for a player who
  drifts or shaves traffic. Races are the exception to "bronze at skill
  0.80": the autopilot at 1.00 with no boost should finish 3rd or 4th.
- **Rivals** are the last `N_RIVAL` slots of the traffic arrays (so drafting,
  contact and placement are traffic's code) on a kinematic model: speed from
  `t_v2` (the autopilot's corner plan, precomputed per tile with braking) x
  skill, an engine curve (`RV_POWER`), lane choice by cost one rival a frame,
  the car ahead as a ceiling, +-3% rubber band over 300 m (`RV_BAND`). With
  `RV_POWER` 385 a skill-1.0 rival is about 0.5% quicker than the autopilot
  at skill 1.0 on an empty road. Race events carry no traffic: the autopilot
  loses 5-15% of its pace to its own panic braking in traffic, which made
  position meaningless as a measure.
- **Themes** are a palette row in drive.rhai (every `P_*` / `S_*` array and
  `S_NUM` has one entry a theme, in `tour::theme_names()` order) plus a
  scenery rule in `gen_road`. To add one: a row in each array, a name, a
  branch in the scenery rules. Towers take their glyph ink from `P_TOWER`
  (only while tools/build_scene.py's `ASCII` gives them an `ascii_style`).
- **The save** (`%APPDATA%\kandinski\saves\default.toml` since Flint #726,
  version 2, every key optional; a tool's run keeps its own with
  `--save-dir <dir>`, as tools/menu_flow.py and touch_check.py do, so no
  test ever reads or writes the real one):
  `save_version`, `hi_score` (arcade), `endless_best`, `paint`, and per event
  `m_<id>` (0-3) and `b_<id>` (best result in the type's own unit). Unlock
  rules are `tour::unlocked` / `endless_unlocked`; paints need medal counts.
- **HORIZON** appends a section whenever the car is within 200 tiles of the
  end of the road (`gen_road` with the seed and height the last call ended
  on), cycling `HORIZON_ORDER` with curve, hills and traffic rising.

## How the road works (read before touching drive.rhai)

- The car never moves. `pos` is distance driven; tiles are laid out each frame:
  `x = f*f*c0; dx = -f*c0;` then per tile `place(x); x += dx; dx += curve[seg]`.
  The road is tangent under the car and bends away ahead.
- A tile is **sheared**, not yawed or pitched: `set_shear(tile, #{ xz, yz })`
  (Flint #625), `xz = -dx / SEG` for the bend and `yz = -dy / SEG` for the
  hill, so edges, the 500 m ground grid and every joint stay continuous. One
  entity a tile (`tile_i`).
- Tile `j = seg % N_TILES`; parity picks `tile_a`/`tile_b`, so N_TILES is even.
  A tile is recoloured only when it is reassigned (`tile_seg[j] != seg`), which
  is why a new section's colours arrive from the horizon. A road is `n_sec`
  sections; `stage_start[k]` is where section k begins (the last entry is the
  goal), `sec_theme[k]` its theme, `stage` the section the car is in.
- Scenery, traffic and gates are pools placed from the same `vis_x/vis_dx/vis_y`
  arrays. A pool entity the road does not need is hidden (`set_visible`,
  Flint #628): scenery by its `used` / `used_prev` counts, traffic and rivals
  by `tr_shown`. A hidden root hides its body and wheels.
- Tile length 8 m is `L` in gen_tiles.py and `SEG` in drive.rhai: change both.

## How the car works (read before touching drive.rhai's "car" block)

- **Road-relative.** State is `speed`, `px` (lateral offset), `yaw` (nose vs
  road tangent), `dir` (velocity vs road tangent), `yawr` (inertial yaw rate),
  all + = right. Slip = `yaw - dir`. The road turns under the car: each
  sub-step `yaw` and `dir` both lose `kappa * v * cos(dir) * h`, with
  `kappa = curve / SEG^2`, so a bend must be steered. There is no `push` term.
  `px += v sin(dir) h`, `pos += v cos(dir) h`.
- **Two axles, saturating tyres** (a bicycle model in acceleration units):
  `F = D * sat2(CORNER * slip_angle / D)`. `D` is what the axle has now: `MU`
  x downforce x surface x crest load (`nload`, from `t_y`'s second difference)
  x weight transfer, and for the rear x handbrake, power, wheelspin. `FRONT`
  < 1 makes the limit understeer. Lateral accel is the axles' mean; yaw accel
  is `KYAW * (F_front - F_rear)`.
- **Assists are what make it arcade** (the `ASSISTS` constants): steering lock
  shrinks with 1/v^2 so full lock always asks about the grip limit; `CASTER`
  > 1 turns the front wheels past the travel direction in a slide, so holding
  the stick INTO the bend holds a drift (about 20 deg), letting go straightens
  it and opposite lock snaps it straight; slip-rate damping; a soft wall at
  `SLIP_SOFT`; past `SLIP_SPIN` (39 deg) it is a spin-out (`crash_t`, one turn).
- **Sub-stepped**: `h <= 6 ms`, 2-9 steps a frame, so 30, 60 and 144 fps agree
  (tools/telemetry.py --rates shows it). Filters use `ease(k, h)`, never
  `min(1, dt * k)`.
- **Crashes go through the state**: an impact kicks `speed`, `dir` (lateral
  velocity) and `yawr`; only a big closing speed or a roadside prop starts the
  scripted two-turn spin (`crash_t`), which ends with yaw back at 0.
- **Entities**: `car` (root: `px`, road pitch, heading) -> `car_body` (model
  `car_player`, body only: spring roll/pitch/heave, capped so the arches clear:
  roll 3 deg, pitch 2 deg, `ARCH` 0.10 m shared) and `wheel_fl/fr/rl/rr`
  (model `car_wheel`, hubs in build_scene.py `WHEELS`; left wheels are the
  same model yawed 180 deg in script). Paint overrides go on `car_body`
  (`body`, `body_hi` = x2, `body_shade` = x0.36, `trim`, `tail`, `under`);
  never override `glass`.
- **Boost / scoring hooks** are published in `game_state` (schema has every
  field): `boost`, `drift_score` / `drift_banked` / `drift_total`, `air_time`
  / `air_total`, `draft` / `draft_time`, `near_count`; events `drift`, `air`,
  `spin`, `boost`.
- **The autopilot** (the attract loop, `auto_s*`, `ev_*`, `ap_assist`) is three steps in the
  input block: lane by traffic cost, speed from the bends ahead against the
  grip they will have (x `ap_skill`), steering as a PD on `px` turned into
  lateral acceleration. Check it with `python tools/telemetry.py stages` after
  touching the car: it must finish the full run with no crashes.
- **Handling tests** are scenes with `game_state.manual` (hands on, no clock),
  `test_track` / `test_curve` / `test_wide`, `cruise`, `telemetry`: see
  tools/telemetry.py's MANOEUVRES. Re-run it after any tuning change and look
  at the plots.

## Gotchas

- **The world is unlit**: `[environment]` ambient 3 with `shadows = false`
  and `default_lights = false` (Flint #627): no light entity, no shadow pass.
  Colour x 3 = radiance. Colour 1 blooms; dark paint is 0.003-0.03; anything
  over ~0.1 already reads bright. Nothing uses glTF emissive: Flint can
  recolour emission now (#624, `set_material_emissive`), but every palette
  and generator here is written as base colour under that ambient, and
  moving them would change every colour in the game for no gain in the look.
- Models are ONE node / ONE mesh, a primitive per named material
  (`tools/glb.py`). Material names are the script's contract
  (`set_material_override(id, "edge", ...)`). Thin cards (fronds, the
  roadside shapes) are one layer of triangles in a `double_sided` material
  (`both_sides` in gen_models.py; Flint draws both faces since #623).
- Rhai: top-level `let` state is visible in callbacks, NOT in helper
  functions. on_update is one long function on purpose; helpers are pure.
  Ints and floats never mix (`i.to_float()`, `x.to_int()`).
- One-shots are named by path here (`play_sound("audio/crash.ogg")`); the
  bare stem works too since Flint #629. Loops are `audio_source` entities at
  volume 0; audio.rhai only moves volume and pitch.
- HUD lettering has two helpers. `neon_text` has a real `glow` (Flint #626:
  one cached picture a label, rebuilt when the text, its size or the glow
  changes, about a millisecond each): words and slow counters only, and keep
  the glow's own alpha fixed. `glow_text` is the thin 1 pt stroke: figures
  that tick every frame, and anything whose size animates. The title
  wordmark (Monoton, 104 pt) has no glow: it asked for an 11205 px texture
  and the player exited. Flint #657 fixed that (halos fit the GPU), so a
  glow there is worth trying again; nobody has yet.
- **Script API names** follow Flint ADR 0116 (verb first, `get_`/`set_`, one
  opts map a draw call: `draw_rect(x, y, w, h, #{ color: [r, g, b, a],
  rounding, layer })`). `flint script check scenes/kandinski.scene.toml
  --schemas engine/schemas --schemas schemas` must say "no problems": it
  catches a deprecated name, a missing function and a wrong argument count
  before the game runs (a script that fails to compile is silently absent).
- **Settings** belong to hud.rhai, the one script awake while paused. The
  screen opens from the title (drive.rhai's mode `settings`, left when the
  HUD sends `cmd = "back"`) and from the pause menu (`s_open`, no mode
  change). Sliders `s_music`, `s_sfx`, `s_pulse`, `s_fx`, `s_shake` (0-1) and
  choices `s_quality` (0-2, `set_quality`) and `s_units` (km/h, mph) are
  loaded once from the save (`set_music`, `set_sfx`, `pulse`, `set_fx`,
  `set_shake`, `set_quality`, `set_units`), saved on every change, and
  published as `game_state.pulse / vol_music / vol_sfx / shake_amt / fx_amt`
  for drive.rhai and audio.rhai to read each frame. A slider takes left /
  right, or a tap anywhere along its bar. RESET PROGRESS (title only, two
  presses within 3 s) clears the save, writes the settings back and sends
  `cmd = "erase"`, on which drive.rhai forgets its medals. To add a setting:
  a `let s_*`, a row in the settings block (names, helps, and its kind by
  index), the load and both save lists, and a `game_state` field if another
  script needs it. tools/touch_check.py holds the title and pause rows by
  formula: change both together.
- **The pulse** (the world moving with the music; a Settings slider, and M
  steps it off / half / full; saved as `pulse`; scene keyword `pulse`). Three parts:
  - `scripts/lib/beat.rhai`: for each loop, a digit 0-9 a sixteenth for
    `kick` (low onsets) and `high` (bright onsets), measured from the OGGs
    by tools/gen_beat.py. Regenerate it whenever gen_audio.py changes the
    music, and read its check line (kicks found against kicks scored).
  - drive.rhai's "pulse" block: `mus_t` counts `delta_time()` from the
    scene's first frame, which is when the loops start; the title loop is
    read under title / tour / brief, the drive loop otherwise. A hit is
    full at its sixteenth and falls away over the next two. Each tile reads
    the music as it was `d / WAVE_V` seconds ago, so a hit runs down the
    road away from the car: the grid takes it (`tile_grid` holds each
    tile's resting colour), and in the scenery loop so do tower windows
    (one building in three follows `high`) and the trees' trim. The sky
    takes `kick_now` / `high_now`: `sun_size`, `halo`, `glow_gain`,
    `stars`, bloom, and `echo` / `echo_phase` (rings leaving the sun on
    the beat, in styles/horizon.wgsl).
  - It is two clocks agreeing, not one: the script clock against the sound
    card's. `PULSE_LAG` is the trim. Flint now has a playback clock for a
    script (`audio_position`, #658), not yet used here; it is the way to the
    pulse on the web too. On the web the loops start when
    the late bundle lands, which no script can see, so `pulse_ok` is false
    there and the pulse stays off. Under `--frame-step` the script clock is
    exact, so a capture muxed with the OGG from t = 0 is in step by
    construction (that is how the presentation's film was made).
- Wheel rotations are quaternions (`q_mul(q_y(steer), q_x(spin))`); euler
  order would roll the wheel about the wrong axis once it is steered.
- hud.rhai owns pause: `on_draw_ui` is the only callback that runs while paused.
  The pause menu's choice reaches drive.rhai as `game_state.cmd` (restart | quit).
- Sample the road at a distance, never at a tile index. Anything visible read
  from `vis_x` / `vis_y` / `vis_dx` at a fixed index slides 8 m and snaps back
  at every tile joint (the camera pumped on every slope until it was fixed);
  interpolate between tile starts at a fixed distance, as the camera, traffic
  and rivals do. The height under the car is a Catmull-Rom through the joints.
- Escape closes the window, and `back` is Backspace / B. Flint lets a game
  bind Escape now (#639), and a script can end the run with `quit_game()`
  (#659), so Escape to pause plus a QUIT on the title is possible; it is not
  done yet, and binding Escape without that QUIT would leave only Alt+F4.
- **Touch** (a phone or tablet, sideways). Three parts:
  - `config/input.toml`'s `[touch_controls]`: a floating stick on `steer`
    (x only), BRAKE, DRIFT (`handbrake`), BOOST and the menu button (`pause`,
    beside the clock: the corners are the HUD's and a notch's). Offsets are
    points and do not scale; the dash scales with the screen's height, so
    check both sizes after moving anything (`tools/touch_check.py`).
  - hud.rhai has them out only in `countdown` and `drive` and not while
    paused (`set_touch_controls`); every other screen is tapped. A tap is
    tested against the very rectangle its row is drawn from (`hit(taps, r)`
    in the draw loop: there are no separate hit boxes) and what it chose
    goes to drive.rhai as `game_state.cmd` (`title:n | ev:n | paint:n |
    res:n | ok | back`), where it sets the cursor and confirms in one go.
    Rows are at least `TOUCH_MIN` (44) points tall whatever the device, so
    nothing moves under the first finger; BACK / START buttons and the
    thumb wording appear while `touch` (the last device was a finger).
  - drive.rhai: while `touch_controls_visible()` the gas is automatic
    (BRAKE is the only way to slow) and the stick takes the pad's curve at
    any deflection. A finger holds the one control it landed on until it
    lifts, which is why there is no GAS button to hold.
  - Under Chrome's device emulation an emulated DPR other than the
    monitor's draws everything measured in points too big (the canvas gets
    the monitor's pixels, egui the emulated ratio): `web_touch.mjs` runs at
    DPR 1. `?perf=1`'s panel lies over the menu button; the script lets
    fingers through it. Flint #660 gave scripts `safe_area()` (the notch's
    insets) and `is_touch_device()` (touch-first before the first touch);
    neither is used yet.
- A menu action is a button: stick directions are `gamepad_axis` bindings with
  `direction` + `threshold` in config/input.toml.
- Slow-changing `game_state` fields (menus, results, the save) are written
  only when `dirty` or every 30th frame: set `dirty = true` when you change one.
- Script update order is not deterministic; hud/audio read `game_state` a
  frame late by design.
- Engine changes go in `engine/`, tested here, then
  `git subtree push --prefix=engine engine <branch>` and a PR to Flint.
- **Taking a newer Flint**: `git subtree pull --prefix=engine engine main
  --squash` (stash first: it refuses a dirty tree), then `bash
  engine/scripts/changelog.sh since <day of the last pull>` lists every
  change a game can notice, each with what to do. Then build, `flint script
  check`, and compare frames: `tools/shot.sh` on the same `auto_s*` scene and
  time is pixel-exact between engines when nothing visible changed.
